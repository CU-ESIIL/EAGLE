# LANDFIRE Reference Database (LFRDB): ingestion and cleaning pipeline

Scripts that download the public LANDFIRE Reference Database, filter it to plots with trustworthy GPS coordinates, match each plot to the closest-in-time 3DEP lidar product, and write the evaluation table in [datasets/LFRDB_eval/](../../datasets/LFRDB_eval/README.md) (read that README for columns, caveats and recommended use).

## Where the raw data came from, and when

- **What**: public LANDFIRE Reference Database (LFRDB), version LF 2.0.0 (LF 2016 Remap): vegetation and fuel plots contributed by USFS, USGS GAP, NPS Inventory and Monitoring, state programs and others. "Certain proprietary and/or sensitive data were removed in the public database"; the source flags (`PublicAccess` in `lutdtVisitsSourceID`) include "plot locations excluded" for some sources.
- **Where**: https://landfire.gov/reference/lfrdb/lfrdb_data . One zip per LANDFIRE geographic area (AK, HI, IA, SW, SC, SE, NE, NC, NW), `https://landfire.gov/data-downloads/zip/LFRDBs_and_Photos/<REGION>/<REGION>_Public_LFRDB_LF2.0.0.zip`. Each holds one Microsoft Access `.accdb` and the data dictionary PDF (`LFRemap_PUBLIC_LFRDB_DataDictionary.pdf`).
- **When**: downloaded on **2026-10-08** (UTC) with `01_download.py`; the servers' Last-Modified dates are 2026-03-17 (AK, HI, IA) and 2026-03-20 (the six CONUS regions). `catalog/download_log.csv` records, for every region, the URL, UTC download time, Last-Modified, zip size and sha256 of the zip. A copy of that table is written next to the raw files in `datasets/raw/LFRDB/SOURCE.md`.
- **Stored in**: `datasets/raw/LFRDB/<REGION>/` (gitignored, 2.1 GB): the `.accdb` files and dictionary, unmodified; the zips were deleted after extraction (their hashes are in the log). Tables exported from the databases are in `<REGION>/tables/` and the intermediate matched table is in `derived/`; both are regenerated by the scripts.

## Run order

Run from the repo root with `pixi run python data_cleaning/lfrdb/<script>`. Each step is rerunnable; stage 1 skips regions already downloaded.

| script | does | writes |
|---|---|---|
| `01_download.py` | downloads and unzips the nine regional databases, logs provenance | `datasets/raw/LFRDB/<REGION>/`, `catalog/download_log.csv`, `datasets/raw/LFRDB/SOURCE.md` |
| `02_extract_tables.py` | exports `dtPoints`, `dtVisits`, `dtCommunities`, `dtStands`, `lutdtVisitsSourceID` to parquet as text (needs `mdb-export` from mdbtools: `brew install mdbtools`) | `datasets/raw/LFRDB/<REGION>/tables/` |
| `03_filter_and_match_als.py` | joins the tables, applies the coordinate and visit filters, looks up the ALS product for each (lat, lon, year), keeps matches within +/-3 years | `datasets/raw/LFRDB/derived/lfrdb_gps_als_matched.parquet`, `catalog/filter_counts_stage3.csv`, `catalog/height_nulling.csv` |
| `04_summarize_matched.py` | plots community-type counts, structure variables, ALS match and map **before** the missing-label filter | `datasets/LFRDB_eval/figures/01-04_*.png`, `catalog/ecosys_counts_matched.csv` |
| `05_finalize_eval.py` | drops rows without a usable `ecosys` label, makes the 50% spatial test split, exports | `datasets/LFRDB_eval/lfrdb_eval.parquet`, `ecosys_split_counts.csv`, `figures/05-06_*.png`, `catalog/filter_counts.csv` |

## Cleaning rules

| rule | why |
|---|---|
| `LocMeth == 'G'` | location was captured with a GPS unit in the field (`M` = digitized in the office, `X` = unknown) |
| at least 5 decimals in lat and lon, counted in the exported text with trailing zeros ignored (5 decimals is about 1 m) | the `G` flag is not sufficient: plots from sources marked "plot locations excluded" are flagged GPS but rounded to 3 or fewer decimals. A coordinate whose last digit happens to be 0 counts as one decimal fewer, so a few well-located plots are dropped |
| visit `Type == 'field visit'` | other types (aerial survey, helicopter survey, photo interpreted, remote) are not plot visits on the ground. Added beyond the filters in the original task description |
| ALS match with `get_nearest_year_product(lat, lon, year, source="AWS")` | picks the covering 3DEP project with the closest collection year, as in the butterfly, BBS and OFO datasets |
| keep `year_diff_AWS <= 3` | matches the +/-3 year rule used for the other datasets |
| drop null `ecosys` and `Unclassified ...` classes | the primary evaluation column; Unclassified classes are lifeform fallbacks |
| heights above 120 m (tree), 20 m (shrub) or 10 m (herb) set to null | unit or typo errors in the source; no matched row was affected |

The decimal-count and visit-type filters are applied before the ALS lookup, so the lookup runs on about 215,000 plots. Source tables carry the same `EventID` in every table, which is unique across the nine regions.

## Requirements

`pandas`, `pyarrow`, `geopandas`, `matplotlib`, `numpy` (all in the pixi environment); `mdb-export` from mdbtools for stage 2; network access for stage 1 only. Stage 3 needs `datasets/USGS_3dep/usgs_3dep_resources_AWS.geojson` (in the repo).
